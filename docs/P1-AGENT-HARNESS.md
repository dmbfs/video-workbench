# P1 方向稿：分镜顾问 Agent 化（model + harness）

> 状态：方向稿，未开工。M4/M5 收尾后按 `skills/superpowers/writing-plans` 产出正式实施计划。
> 依据：PRD §3 P1「自主 Agent（自动多轮改写并触发生成）」；用户定义 `Agent = model + harness`。

## 1. 定义：harness 必须包含什么

`Agent = model + harness` 成立，但只有把 harness 拆开才有指导意义——否则任何"模型 + 脚手架"都能自称 agent。model 决定能力上限，harness 决定可靠性；同一 model 换 harness，可以是从聊天机器人到能干活的分水岭。harness 至少要提供五件事：

1. **工具（actuators）**：agent 能对世界做什么，以及每个动作的契约与权限
2. **循环（loop）**：观察 → 决策 → 行动 → 反馈，以及何时停
3. **上下文（context）**：每一步模型看到什么状态，而不是全量历史
4. **边界（guardrails）**：预算、超时、熔断、权限、人工闸门
5. **验收信号（verification）**：凭什么判定这一步"变好了"

第 5 条是分水岭：没有可验证反馈的循环只是随机游走。M4 刚加的预算/超时/熔断属于第 4 条，是自主循环的前置条件，不是全部。外部环境（provider API、文件系统、ffmpeg）算第三个词，可写作 `Agent = model + harness + environment`。

## 2. vidstitch 现状映射

- **model**：分镜顾问（BYOK OpenAI 兼容 chat），用户可替换
- **现有 harness**：系统提示词 + JSON schema + zod 校验 + 一次自动重问；生成侧是独立的确定性编排器，与模型不连通
- **缺口**：没有工具层、没有统一循环、没有 per-run 预算、没有轨迹日志
- **结论**：现在不是 agent。P1 要做的是 harness 工程，不是换模型；由于 model 是用户自带且可替换，harness（分镜方法论 + 工具集 + 边界 + 验收信号）才是产品护城河。

## 3. P1 目标 harness

### 3.1 工具集（server 侧执行，key 不出后端）

| 工具 | 作用 | 花钱 | 闸门 |
|---|---|---|---|
| `read_project_state` | 分镜 / 分段状态 / 预算用量 | 否 | — |
| `get_balance` | provider 余额 | 否 | — |
| `edit_storyboard` | 增删改段 | 否 | schema 校验 |
| `regenerate_segment` | 单段重跑 | 是 | 预算 + 确认策略 |
| `generate_all` | 批量生成 | 是 | 预算 + 确认策略 |
| `query_export` | 成片 / 导出状态 | 否 | — |

每个工具 zod 入参/出参；执行结果写回轨迹。

### 3.2 循环

- 每轮：注入 state snapshot → 模型选择一个工具调用 → 执行 → 结果写回 → 再决策
- 停止条件：目标达成 / `max_steps` / token 预算 / 连续无进展 / 用户中断
- 花钱工具默认逐次人工确认；「预算内自动」是显式开关（语义见 §5）

### 3.3 上下文

- 不塞全历史；每步给结构化 state snapshot + 最近一次工具结果 + 剩余预算
- 长对话压缩：保留决策与结果，丢弃原始流

### 3.4 边界（复用 M4 已有并升级）

- **预算**：项目级（已实现）+ 每次 run 级（新增）
- **超时**：provider 轮询（已实现）+ 单次工具调用 + 整个 run
- **熔断**：连续段失败（已实现）+ 连续无效工具调用 / 无进展
- **花钱闸门**：默认逐次确认 + 「预算内自动」显式开关（已定，见 §5）

### 3.5 验收信号

- 结构：zod 通过
- 生成：段 succeeded + ffprobe 时长 / 分辨率达标
- 一致性：接力首尾帧相似度（漂移检测）
- 终局：用户确认
- **明确不做**：让模型自己判断画质并自动无限重跑（烧钱且不可验收）

### 3.6 可观测

- 每次 run 落 trajectory：step / 工具 / 入参 / 结果 / 耗时 / 花费 / 停止原因
- 支持回放与审计；这是开放自主模式的前提

## 4. 分阶段建议

1. 只读工具 + trajectory（不改变现有行为，先让循环可见）
2. 编辑工具（改分镜，不花钱）
3. 花钱工具 + 闸门（单段重跑先行，批量生成后置）
4. 自主循环（有界，默认人在环）
5. 评估集：固定若干 prompt，跑回归看分镜质量与成本

## 5. 决策记录

- **花钱工具策略（已定，2026-09-09）**：默认逐次人工确认；「预算内自动」是显式开关，默认关闭。语义：
  - 默认模式：每个花钱工具调用前弹确认（显示工具、参数、预计调用次数与花费），用户确认才执行
  - auto 模式：用户按项目显式开启后才生效；开启期间花钱工具在预算内自动执行，不再逐次确认
  - auto 模式的硬约束不因开关而放松：项目调用上限、per-run 调用上限、轮询/工具超时、连续失败熔断全部照常生效
  - 熔断触发、预算耗尽或 provider 切换时自动退出 auto 模式，需用户重新显式开启
  - 每次花钱调用都落 trajectory，auto 模式只是省掉确认点击，不省审计
- **验收信号（待定）**：是否引入 VLM 打分做画面质量反馈（成本 / 收益待评估）。第一期自主循环只闭环「结构合法 + 生成成功 + 预算内」，画面质量仍由人判定
